When Trackers Fail: VLM-Guided Verification and Recovery for Robust Video Object Segmentation

Memory-based trackers like SAM 3 fail silently: one wrong prediction enters the memory and is propagated forever. Dual-Agent adds a verifier that notices and a corrector that recovers, with the tracker left frozen.

The problem: propagation has no way to notice it is wrong

SAM-style trackers predict each frame from the current image and a memory of their own past predictions. That recursion is their strength and their weakness: once a wrong mask is written into memory, every later frame reads from it. Better memory design delays this; nothing in the loop detects or repairs it.

Identity switch

A look-alike passes close by and the mask jumps to it. The memory now describes the wrong object, so the track stays on it.

Missed reappearance

The target leaves and comes back, after an occlusion or a scene cut. The tracker keeps predicting nothing, or a stale box.

False positive during occlusion

While the target is hidden, the tracker fires on background or a distractor, and that mask is remembered as the target.

Rows: ground truth, SAM 3, Dual-Agent. Once SAM 3 loses the target it does not come back on its own; Dual-Agent recovers it and tracking continues normally.

The idea: verify, then recover

Keep the propagator frozen and add a thin control layer with two specialists. A verification agent decides whether the track is still the target. A correction agent, called only on a detected failure, decides where the target is. A committed correction re-prompts SAM 3, so propagation resumes from a clean state instead of a corrupted one.

One triggered frame, step by step

Trigger: look only when something is off

Three cheap signals from SAM 3 itself decide when the agents run: polling every few frames during an occlusion, a delayed check after a reappearance, and an early-warning trigger that fires when the tracker's own confidence becomes unstable over a short window, which happens during identity swaps and distractor attraction before any hard disappearance. Thresholds are calibrated once on a held-out SA-V shard and never tuned on the benchmarks.

Short-circuit: if SAM 3 is confident, trust it

At a triggered frame the propagated prediction is accepted directly when SAM 3's confidence is high. Reasoning is spent only in the uncertain regime where memory corruption is likely.

Verify: a VLM judges the track from the tracker's own history

The verifier (Qwen3-VL-8B-Thinking, zero-shot) sees a seven-image prompt: two early exemplars with ground-truth boxes in green, two uniformly sampled and two recent context frames with the tracker's own boxes in red, and the query frame. The context is the possibly corrupted trajectory the deployed tracker produced, not an oracle one. The prompt asks the model to first locate the target itself and only then judge the red box, which promotes identity-level reasoning over local box checking. Three votes on shifted query points (stride 4) are majority-pooled.

Correct: a fine-tuned VLM relocalizes the target

Only when the verifier says "wrong", the corrector (Qwen3-VL-4B-Instruct, LoRA fine-tuned) receives the same prompt and answers a visibility flag plus a box. Up to three rounds: the verifier re-checks the proposed box and, if rejected, the corrector tries again with the rejected box as extra context.

Commit: rewrite memory only when it matters

A correction overwrites SAM 3's state only if it differs substantially from the current hypothesis (box IoU < 0.5) or declares the target absent. SAM 3 is then re-prompted at that frame. One wrong commit can pollute many future frames; one right reset recovers a long segment after drift. This asymmetry is why triggering is sparse and commitment is conservative.

Four design decisions behind it

Asymmetric decomposition

Deciding whether the track is wrong and where the target is are different tasks. The verifier is tuned for precision in deciding to intervene; the lighter corrector is tuned for accuracy in localization.

Tracker-aware reasoning interface

The verifier reasons over the trajectory the tracker actually produced, trusted exemplars plus possibly corrupted context. Clean oracle context would be an easier problem than the one faced at inference.

State-safe intervention

Sparse triggers decide when to look; a confidence short-circuit and a commit gate decide whether a correction may rewrite the tracker's memory.

Failure-oriented supervision

The corrector is trained on failures mined from real SAM 3 runs, plus identity-switch and distractor perturbations that reproduce the ambiguities that make propagators fail.

Trained on real failures

Supervision must match the failure distribution the corrector will see at test time, so the training data comes from SAM 3's own trajectories, not from oracle tracks.

  • Mine failures from SAM 3. SAM 3 is run on SA-V shards sav_000 to sav_005 (5,145 sequences, 16,045 objects) from each object's first-appearance mask. Every annotated frame records the prediction, its confidence, its IoU to ground truth, and a set of visually similar distractor candidates.
  • Sample where it goes wrong. Query frames oversample disagreement with ground truth and keep a small share of high-IoU frames. Each query is rendered as the same seven-image prompt used at test time, with the target visibility and ground-truth box as the answer.
  • Inject identity ambiguity. With some probability, one or two recent context boxes, sometimes the query box too, are replaced by mined distractor boxes from the same frame. The corrector learns to reason about identity across time instead of trusting local appearance.
  • Corpus. 79,457 samples, split by sequence into 75,341 train and 4,116 validation. The corrector is a Qwen3-VL-4B-Instruct backbone fine-tuned with LoRA on structured JSON answers.

Limitations

  • It is only as good as the verifier. In highly ambiguous scenes the verifier can miss a failure or trigger an unnecessary correction; 9 of the 52 checkable commits on SecVOS overrode a track that was already right, and the seen-class scores on LVOS-v2 dip slightly for the same reason.
  • Not real-time. Verification adds a VLM call at triggered frames; the full system is about six times slower than SAM 3 per video on an H100, and about four times with FP8 and sparser polling.
  • Protocol caveats. The LaSOT-ext result is a size-selected composite rather than an unrestricted online policy, and VOT-LT trades some precision for recall.
  • Unverified scope. Transfer to specialised domains, and video-level disjointness between the benchmarks and the VLMs' pretraining data, have not been established.
